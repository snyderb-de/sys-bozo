Baller TUI

One command to manage the machine.

`sys-bozo` should grow into a visual terminal control center for updates, packages, config editing, audits, secrets, and host sync.

sys-bozo

Core rule

Plan first. Apply second.

Every screen creates an explicit plan before it mutates files, package managers, or system state.

PreviewShow exact changes

Files, symlinks, package installs, package removals, config writes, and commands appear before execution.

ApproveConfirm grouped work

Apply all, apply selected tasks, or back out without changing the machine.

RecordKeep local history

Save last runs under `~/.local/state/sys-bozo/` so audits can explain what changed.

Package manager reality

Selected updates are easy in Brew, trickier in Nix.

The TUI should be honest when a package manager cannot safely do the exact thing the user asked.

Homebrew

`brew outdated --json=v2` can feed a package picker. Then `brew upgrade foo bar` updates selected formulae or casks.

Nix flakes

Most packages follow one `nixpkgs` input, so “update only yazi” may require pinning, overlays, or profile installs. Default TUI action should update inputs by scope, then explain exceptions.

Nix policy

Be an editor, planner, validator, and verifier first.

Do not build clever Nix abstractions before the boring human-editable shape is trustworthy.

RuleDecisionReason
Package listsKeep direct Nix lists human-readable first.`home.packages = with pkgs; [ bat eza yazi ];` is easier to debug than an early generated variable maze.
Adding packagesSearch, ask Nix or Brew, open the right config, show diff, apply, verify.The TUI should assist the declaration instead of hiding it.
Nix updatesUpdate flake inputs by scope/input unless explicit pin/overlay support exists.Most Nix packages share the same `nixpkgs` snapshot; pretending otherwise is lying with extra steps.
Generated configDefer generator output until catalog/profile tests are strong.Early magic creates debt faster than it creates repeatability.

Package flows

Search should end in a catalog change, not a random one-off install.

Search: yazi Found: nixpkgs: yazi 25.x brew: yazi 25.x Choose: [ ] Install now only [x] Add to sys-bozo catalog [x] Include in current host profile [ ] Install with Brew instead of Nix Plan: edit catalog/tools.yaml edit host profile run nix/home-manager apply verify `yazi --version`

Move flows

Moving between managers must verify replacement before uninstalling the old copy.

MovePlanSafety check
Brew to NixFind Brew owner, search nixpkgs, add catalog entry, apply Nix profile, then offer Brew uninstall.Only uninstall Brew after command resolves to Nix path and version works.
Nix to BrewFind catalog entry, search Brew formula/cask, update host/profile choice, apply Brew install.Only remove Nix declaration after Brew binary or app bundle verifies.
TarballDownload or use local archive, checksum when possible, unpack under chosen target, symlink command.Default target is `~/.local/opt/name/version`; uninstall manifest required.

Build shape

Go TUI with Charm stack.

Use Go for one portable binary, Bubble Tea for app state, Bubbles for widgets, Lip Gloss for visual polish, and a planner package underneath.

UI layer`internal/tui`

Navigation, tables, search boxes, checklists, progress, preview panes, command palette.

Planner`internal/plan`

Pure functions returning actions. Tests inspect actions without touching the machine.

Adapters`internal/managers`

Nix, Brew, Git, SSH, SOPS, tarball, and editor operations live behind small interfaces.

StateXDG paths

Config in `~/.config/sys-bozo/`; cache in `~/.cache/sys-bozo/`; run history in `~/.local/state/sys-bozo/`.
