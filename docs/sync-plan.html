Policy

Sync Plan

The goal is not identical machines. The goal is identical intent: shared defaults everywhere, explicit host differences where reality demands it, and install profiles that do not require buying into every tool at once.

LayerAuthoritySync policy
CLI and TUI packagesNix profile or plain checklistShared baseline across selected hosts.
GUI appsHomebrew casks when enabledShared baseline plus explicit host-only additions.
Mac App StoreMAS-only BrewfileManual run until MAS is pulled into an apply flow.
Shell configHome Manager or shell installerShared, with private overrides in local files only.
SSH aliasesSOPS private configNever public. Decrypt into XDG config.
Host factsHOST_MATRIX.mdPublic only when not sensitive.

Order of operations

Short version: fix plumbing before adding ceremony.

0. Get Tailscale SSH working across all devices 1. Make dotfiles-audit compare canonical hosts 2. Import the sys-bozo CLI/TUI tools through Nix 3. Add iTerm2 through the optional Homebrew module 4. Define sys-bozo install profiles 5. Split flake.nix into hosts/ and modules/ 6. Add Linux profiles after the module boundaries are clean

Host difference policy

Make differences intentional.

The Mini and MacBook do not need to match. They need declared reasons for not matching.

BucketExamplesAction
Shared baselineCore CLI/TUI tools, shell behavior, Git defaults, editor defaults, SSH include pattern.Move into shared module/profile.
Mini-onlyDisplayLink, Stream Deck, desktop utilities, server-ish helpers, apps tied to desk setup.Declare in mini host profile.
MacBook-onlyBattery/lid policy, laptop-only apps, travel/workflow tools, alternate display sleep.Declare in laptop host profile.
Manual/privateSSH aliases, tailnet details, work VPN/auth, app licenses.Keep in SOPS/private includes or manual checklist.
Cleanup candidatesPackage manager duplicates, old apps, PATH-only drift, one-off Brew leaves.Review before declaring.

DEC-006 research

Closed-lid SSH needs care.

Apple supports wake-for-network and closed-display style workflows, but preventing sleep can increase power use. Treat always-on closed-lid SSH as a researched policy decision, not a default.

OptionProsCons
Supported clamshellNormal Apple path with power/external-display style setup.Not a pure headless laptop server mode.
Maintenance modeUse `caffeinate` only while actively working over SSH.Manual session management.
`disablesleep`Most likely to keep SSH alive when closed.Battery drain, heat risk, and easy to forget.
Leave lid crackedSimple and low-risk during setup.Not elegant.

Sources to review: Apple sleep and wake settings, Apple external display guidance.
