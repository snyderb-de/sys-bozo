Composable install

Install shapes

sys-bozo should be installable as a set of opt-in profiles. A machine can adopt the docs, the shell, Nix packages, Homebrew apps, Home Manager config, nix-darwin settings, or any combination that makes sense.

ProfileRequiresInstallsUse when
docsbrowserHTML docs onlyYou want inventory and runbooks without touching the machine.
shell-litePOSIX shellXDG directories, safe links, checksYou want structure without Nix, Homebrew, or Home Manager.
cli-nixNixCLI/TUI toolsYou want repeatable command-line tooling without macOS system management.
home-managerNix + Home ManagerUser config, packages, shell, gitYou want managed dotfiles but not nix-darwin.
brew-appsHomebrewGUI casks and fontsYou want app sync without Nix.
darwin-fullNix + nix-darwin + HomebrewSystem defaults, HM, appsYou want the full macOS managed host.
linux-homeNix + Home ManagerLinux user environmentYou want the shared sys-bozo layer on Linux.

What must exist

Implementation roadmap

Buying a new MacBook or installing Linux should become a guided, reversible install. No mystery mutation. No “hope brew exists.” No package-manager hostage situation.

CapabilityWhat it doesWhy it matters
Bootstrap scriptRuns with plain shell, detects OS/arch/package managers, creates XDG dirs, and can install only docs or shell-lite.First contact must not require Nix, Homebrew, or Home Manager.
Profile manifestDefines profiles like docs, shell-lite, cli-nix, home-manager, brew-apps, darwin-full, linux-home.Management style becomes data, not scattered conditionals.
Tool catalogStores every tool with category, package names per manager, default profile membership, and dependencies.Excluding tools requires a catalog, not hand-editing Nix lists.
Exclusion supportAccepts `--exclude` and persistent host exclusions.New machines can opt out of heavy, silly, GUI, or work-only tools.
Dry-run plannerPrints files, links, packages, casks, secrets, and commands before applying.Installers should earn trust before touching a fresh machine.
Module outputsGenerates or selects Nix, Home Manager, nix-darwin, Homebrew, and shell-lite actions from the same catalog.One sys-bozo inventory, many management methods.
Host identity flowPrompts for canonical host name, role, user, OS, and privacy-safe labels.Many machines need consistent names without leaking private aliases.
Secrets handoffChecks for age key/SOPS access and gracefully skips private fragments if unavailable.A public installer must not assume private secrets exist.
Audit integrationCompares declared profile to installed state after install.Install success should be measurable.

The important part is choosing what not to install without forking the whole setup.

Yes: once sys-bozo is more than a static sketch, use a framework or generated utility CSS. The practical choice is a build step that emits local CSS, not a CDN dependency. Amazing-looking docs, no network dependency, no mystery runtime.

Module answer

Every installer should have a dry-run and explain exactly which files, packages, and app managers it will touch before doing anything.

Testing model

How we test without wrecking the machine.

sys-bozo should prove what it will do before it touches a real home directory, package manager, or system setting.

Step onePlan first

`sys-bozo plan` prints the folders, files, packages, casks, and secret checks it would perform. Tests can inspect that plan without changing the computer.

Step twoApply later

`sys-bozo apply` should only run after the plan is correct. The mutating layer stays separate from the planning layer.

Local safetyFake home

Tests create a temporary fake home like `/tmp/sys-bozo-test-home` and verify writes there instead of touching `/Users/bag`.

LinuxContainers

Docker or Podman can test Linux flows cheaply: no-Nix, Nix-present, Home Manager-present, and missing dependency cases.

macOSReal Mac runners

Docker cannot test macOS. macOS behavior needs GitHub Actions macOS runners, a macOS VM, or a spare test Mac.

Full installDisposable VM

End-to-end “new MacBook” or “fresh Linux” tests should run in disposable environments, not on the daily driver.

Plan, then apply

The installer should sound boring before it becomes powerful.

# Safe: describes intended work sys-bozo plan --profile darwin-full --exclude zellij,fun-tools Would create: ~/.config/sys-bozo/ ~/.config/sops/age/ Would install Nix tools: eza bat yazi Would install Homebrew apps: iterm2 raycast Would skip: zellij fun-tools # Mutating command comes later, after the plan is trusted sys-bozo apply
